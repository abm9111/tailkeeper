# Security evidence contracts (internal, version 1)

These Go DTOs are mutable Go values: copies of slices, maps and pointers are shallow. Producers and retainers must establish ownership and deep-copy nested data at their boundary. These Go DTOs are an internal foundation, not a public assessment API. Private replay and stateless correction verification are provided by `internal/securitypack` and its owner-only commands; see [evidence packs](evidence-packs.md). A report is a point-in-time record of bounded observations, findings and independent coverage; a complete report is not a safety guarantee. Input carries a catalog, snapshot and optional owner intent. A correction carries schema version 1, an action time, finding targets by rule and device, selected expectation IDs, and typed expected versions or features with a device and role. Expectations contain no observation metadata. The verifier checks identity, rule compatibility and post-action evidence. Lifecycle and event types are provisional shared data only, subject to a dedicated review before use; no transition is implied by constructing them.

Reports carry schema version 1, a context reference, optional key epoch, generation time, snapshot and status. Context and epoch references must be derived by a later identity adapter; display names are not stable identity. Each finding has an ID, rule ID and revision, asset and evidence state. The ID is `FindingID(context, scope, asset, rule ID)`: the lowercase hex SHA-256 of each value written as its byte length, a colon and the value, in that order. The length prefixes make the encoding unambiguous. The rule revision is not part of it, so a revised rule changes a finding and not its identity. This identity is unkeyed and deterministic, not a privacy-preserving pseudonym, and the asset it hashes is a raw reference; this model does not create or verify keyed identities. Source severity and local action priority are distinct fields.

A finding that is `unknown` or only `potentially_affected` says why in `reason`, a closed set: `catalog_expired`, `review_expired`, `review_pending`, `no_version`, `evidence_error`, `stale_evidence`, `version_conflict`, `unrecognised_build`, `channel_unknown`, `unstable_track`, `os_unrecognised`, `os_unknown`, `feature_unknown` and `runtime_unobserved`. A finding that is affected or not affected has none, and the field is omitted when empty. A coverage row can carry `counts` (`rules`, `withdrawn`, `assets`, `findings`, `unknown` and `potential`), the number of each thing it evaluated. The advisory matcher always fills them on its catalog row: `rules` counts the rules it evaluated (approved and pending), `withdrawn` those it skipped, `assets` the devices and `findings` the findings it returns; so a row that stopped early counts what was done. A count of zero is stated, not omitted, and the field is absent when the row has no counts. The schema stays version 1: it is not yet published, so these fields were added in place.

Coverage requests name a closed dimension, scope and optional asset; a complete report requires a matching complete row for every requested target. A row can also say that its target was not requested (status `not_requested`, for instance intent when no intent set is configured), so that the absence is stated and not silent: the status is valid only for a target that is not among the requested ones, needs a source and an explanation and carries no counts, it is never a report's status, and it neither answers a requested target nor keeps a report from being complete. These are structural claims, not verification that the named asset or source was actually observed. Partial reports can omit rows. Each fact has an evidence reference with source class, context, acquisition time, optional source observation time, freshness and a bounded error. A nil value means absent, while a pointer to false or true records that value; stale is separate from both presence and value. A source observation cannot be later than acquisition, and acquisition cannot be later than report generation. Timestamps must be JSON-representable and use a zero UTC offset. No clock-skew allowance is made for reports. Relative ordering does not establish real-world freshness; a future caller must compare with its supplied trusted current time. Freshness is an asserted classification; validation cannot establish it from a clock alone.

`ValidateReport` rejects unsupported schema versions, context and epoch mismatches, invalid enum values, missing essential fields, future evidence, invalid UTF-8, control characters (C0, DEL and C1), invisible or misleading characters (the ones `sanitize` escapes when it renders text: bidirectional controls, zero-width characters, tag characters, variation selectors, blank fillers, the no-break space and other non-ASCII spaces, the line and paragraph separators, the byte order mark, and private-use and unassigned code points; a copy of its test in `internal/security` is held to the same answer for every code point) and oversized strings or collections. Every time must also be representable in JSON, use a zero UTC offset and not precede 2019-01-01T00:00:00Z; the catalog decoder applies the same text and time checks. A truncated report must be partial and its total must exceed the returned count; otherwise the total must equal that count. Complete reports cannot contain partial coverage.

Evidence is tied to the snapshot. The evidence of every version, platform, feature and policy fact carries the report's context and the snapshot's scope (equal, so a snapshot without a scope admits only evidence without one), and version, platform and feature evidence names a device (`asset`); policy evidence may leave it out. A finding that is `affected` or `not_affected` has evidence state `observed`, at least one piece of evidence whose context and device are the finding's, and no `reason`; every piece it cites is fresh and carries no error. A finding that is `unknown` or `potentially_affected` has a `reason` from the closed set above, and an `unknown` one has evidence state `unknown`, `stale` or `absent`. A finding's `id` equals `FindingID` of its context, the snapshot's scope, its asset and its rule ID; IDs are unique, and so is each context, scope, asset and rule tuple. Every piece of evidence a finding cites carries the snapshot's scope, as the evidence of the snapshot's own facts does (the identity hashes that scope); a finding with no evidence, which an unknown one may be, is not asked for a scope. Every piece of evidence a finding cites, whatever its applicability, equals by value (every field, with the observation time compared as an instant and not as a pointer) the evidence of some fact in the report's snapshot, so a finding cannot rest on an observation the report does not contain. A finding has a rule revision, and `corroborated` confidence needs at least two pieces of evidence from distinct origins. A `complete` coverage row names a source and, when it has counts, counts no unknown and no potentially affected finding and at least one rule and one asset; a complete row of the catalog dimension cannot sit in a report that holds an unknown or potentially affected finding. A `partial` row explains why. Counts are never negative, the unknown and potentially affected counts together do not exceed the findings count, the findings count does not exceed 10,000, and when the report is not truncated the findings, unknown and potential counts of a catalog row equal the number of findings, of unknown findings and of potentially affected findings the report holds. Each of these checks has its own error text, and the validator stops at the first. Limits are 4,096 bytes per string, 10,000 total findings and 10,000 elements per report collection. Stateless scan output is separately limited by the plan to 100 findings and must explicitly mark truncation; implementing that limit is evaluator work. Validation must run before serialization: Go JSON encoding replaces invalid UTF-8, so validation after encoding cannot recover the original bytes. Consumers must also impose byte and nesting limits before decoding untrusted JSON, reject unknown fields and duplicate keys at the import boundary, and validate the resulting report. The DTO validator alone is not a safe untrusted JSON decoder.

All strings are data, never instructions or markup. Future renderers must escape terminal control characters and Markdown metacharacters for their output context; JSON encoding alone does not make text safe for a terminal or Markdown. Reports can contain sensitive derived references and require the private persistence and redaction controls in the design. References and source links must be treated as untrusted data, not automatically fetched.

The catalog is a typed input for later acquisition and matching. Its records distinguish component, platform (a canonical OS name), ranges, source, review and severity. `advisory.Decode` is its strict, bounded decoder (see [the advisory contracts](advisories.md)); catalog authentication, monotonicity and freshness are later responsibilities. Snapshot adapters must preserve original field presence. Intent expectations model known network and SSH fields, including source posture attributes and SSH check users. The adapter from the existing checked invariants loader (`internal/tools/security_intent.go`) maps `src`, `proto`, `srcPostureAttrs`, `accept` and `deny` of a test and `src`, `dst`, `accept`, `deny` and `check` of an SSH test, numbers the expectations by position (`network-1`, `ssh-1`) and names the set by a digest of the file's exact bytes (`Digest`: keyed while personal data is masked and a privacy key is loaded, the plain SHA-256 with `personalData: show`, none while masked with no key) and its first twelve hexadecimal digits (`Revision`, none without a digest); the report schema takes any short text as a revision. The keys and their spellings are those of internal/acl's normal form (`acl.PolicyTestKeys`): the deprecated `user` is `src` in a test and the deprecated `allow` is `accept` in a test and an SSH test; a test that gives both spellings of a list is read as one list (`accept` first), and of `src` and `user` together `user` is an unread field. An entry with a field the adapter does not map, a field of another shape or no source is refused, with its kind and its place and none of its words, rather than discarded. Validating the full upstream grammar is deferred. Event and lifecycle schemas will require a dedicated review before persistence or notification use.

Posture attributes preserve typed string, finite number and boolean JSON scalars, including number spelling. Inactive scalar members must be zero, and strings and attribute names are limited to 4,096 UTF-8 bytes; maps are limited to 10,000 attributes. Null, compound values and duplicate attribute keys are rejected. The future policy adapter must enforce the more restrictive native policy-test grammar. Evidence state and confidence are closed classifications of evidence, not numerical probabilities.

Deferred, each to the change that needs it. Strict JSON decoding of `Report`, `Finding`, `IntentSet` and `Event` (unknown fields, duplicate keys and case-insensitive key matching are accepted by the plain decoder) waits for the import path; until then these types must not be decoded from untrusted JSON. Deep-copy ownership of a report that something else retains (a validated report can stop validating if its caller mutates a shared pointer) waits for retention; a report made by `Evaluate` owns its data, but a copy of it is as shallow as any other Go value. Unstable-track advisory ranges wait for a real advisory that needs them. Keyed, privacy-preserving finding identity waits for the output boundary. A canonical content digest of a catalog waits for signed catalog sync.
